# Context

codie uses API keys only. A key may come from an explicit `--api-key`, a stored `auth.json`, or the provider's
environment variable. Keys are never printed, never included in diagnostics, and never written to a session.

`auth.json` lives under the data directory and has this shape:

```json
{"providers": {"deepseek": {"api_key": "..."}, "openrouter": {"api_key": "..."}}}
```

# Requirements

**PROV-030 (MUST)** `auth.json` is written atomically through a private temporary file and renamed into place; on Unix the file mode is `0600`. A missing file is an empty store, and a malformed file is an error rather than silent replacement.
Verification: `crates/codie-ai/tests/auth.rs::store_round_trips_and_is_private`

**PROV-031 (MUST)** Key resolution is explicit key, then stored credential, then the provider's environment variable. Empty or whitespace-only values count as absent, and resolution never falls through to another provider.
Verification: `crates/codie-ai/tests/auth.rs::resolution_order`

**PROV-032 (MUST)** `codie auth login` stores a key without echoing it, `codie auth logout` removes only that provider, and `codie auth status` reports configuration booleans without revealing any part of a key.
Verification: `crates/codie-cli/tests/cli.rs::spec_prov_032_auth_status_reports_configuration_without_secrets`

**PROV-033 (MUST)** Missing-key and malformed-store errors name the provider and the environment variable to set, never a secret value.
Verification: `crates/codie-ai/tests/auth.rs::spec_prov_033_errors_never_include_the_key`

**PROV-034 (MUST)** `--api-key` requires an explicit `--model`, overrides stored and environment keys for that run only, and is never persisted to `auth.json` or a session file.
Verification: `crates/codie-cli/tests/cli.rs::spec_prov_034_api_key_is_ephemeral`

# Security and performance

Credential reads are one small file per run. Writes sync the file and its parent directory. No network call is
made to validate a key at startup.

# Out of scope

OAuth, browser login, and subscription credentials are not supported in v1.
