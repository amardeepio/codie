# Context

`codie --mode rpc` is the editor-integration interface. It is a long-lived process that reads commands from
stdin and writes responses plus the same agent events as JSON mode to stdout. Diagnostics always go to stderr,
so a client can parse stdout without filtering.

Requirements `PROTO-004` (settled as the completion signal) and `PROTO-005` (published schemas) are canonical in
[`0001-json-events.md`](0001-json-events.md). This spec does not redeclare them.

# Transport

```text
{"type":"rpc_ready","version":1}
{"type":"session","version":1,"id":"...","timestamp":"...","cwd":"..."}
{"type":"response","version":1,"id":"1","command":"get_state","success":true,"data":{...}}
{"type":"agent_start"}
...
{"type":"agent_end","messages":[...],"status":"completed"}
{"type":"agent_settled","aborted":false}
```

Records are LF-framed JSON objects. The server writes exactly one response per command, echoing the request `id`
when supplied. Agent events are interleaved between the response and the final `agent_settled`.

# Command matrix

| Command | Fields | Response data |
|---|---|---|
| `prompt` | `message` | `started`, `session`, `warnings`; queues as a follow-up when a run is active |
| `steer` | `message` | `queued`; fails with `no_active_run` otherwise |
| `follow_up` | `message` | `queued`; fails with `no_active_run` otherwise |
| `abort` | — | `aborted`; fails with `no_active_run` otherwise |
| `get_state` | — | session, cwd, model, thinking, active, messages, tokens, context percent |
| `get_messages` | — | projected transcript messages, excluding the system prompt |
| `get_entries` | — | session entry tree |
| `get_session_stats` | — | message and entry counts, tokens, context, last usage |
| `new_session` | — | new session identifier; fails with `run_active` during a run |
| `set_model` | `model`, optional `provider` | model and context window; provider changes are unsupported |
| `set_thinking` | `level` | thinking level |
| `compact` | optional `instructions` | compacted flag, message count, token estimate |
| `export_html` | optional `path` | written path |
| `shutdown` | — | `shutdown`; cancels an active run and exits after it settles |

Unknown commands, invalid JSON, and invalid arguments produce `success: false` with a stable `error.code`
(`bad_request`, `no_active_run`, `run_active`, `invalid_argument`, `unsupported`, `no_session`,
`compaction_failed`).

# Requirements

**PROTO-003 (MUST)** RPC mode reads LF-framed JSON commands from stdin and writes one response per command to stdout, echoing the request `id` and the `command` name, with agent events and a final `agent_settled` interleaved; diagnostics go only to stderr.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_003_rpc_command_matrix`

**PROTO-006 (MUST)** RPC shutdown is orderly on stdin EOF, SIGTERM, or SIGHUP: an active run is cancelled and allowed to emit `agent_settled`, EOF exits 0, and signal exits use 143 and 129. A second signal exits immediately.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_006_sigterm_uses_the_signal_exit_code`

# Failure modes

- Malformed JSON never kills the server; it produces a `bad_request` response.
- A command that needs a session fails with `no_session` when `--no-session` is in effect.
- `compact`, `new_session`, and `set_model` do not race an active run; they fail with `run_active` where the
  result would be undefined.
- A dropped stdout closes the process without losing already-flushed records.

# Security and performance

The server uses the same headless tool policy as `--mode json`: mutating tools are denied unless allowed.
Commands and events contain full transcripts and tool output and are not redacted. The reader is a detached
thread so a signal or `shutdown` never waits on a blocked stdin read.
