# Context

Version 1 of RPC mode is headless: mutating tools are denied unless they were pre-approved with `--allow`, and
credentials can only be supplied on the command line or through a terminal prompt. Desktop clients need to
authorize individual tool calls, store keys without putting them in `argv` or scrollback, discover selectable
models, read and write configuration, and attach files or clipboard images.

Version 2 adds those capabilities without changing the version 1 contract. A client that never sends the new
commands keeps headless behavior. `RPC-003` in [`0002-rpc.md`](0002-rpc.md) remains the command/response framing
contract; this spec only adds commands, one record, and the capability handshake.

Consumers: the desktop app bridge (`desktop-app/`), editor integrations, and the `examples/rpc-client` script.

# Normative behavior

**PROTO-007 (MUST)** Tool authorization defaults to `headless`; `set_permission_mode` switches to `ask` or `allow`, and in `ask` mode every mutating call that is not read-only and not pre-approved emits exactly one `permission_request` record and waits for `permission_response` with `allow_once`, `allow_always`, or `deny`. An abort, shutdown, stdin close, or dropped client denies every pending request; `allow_always` covers the rest of the session; read-only tools never prompt.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_007_permission_request_allows_a_write`, `crates/codie-cli/src/permissions.rs::spec_proto_007_ask_mode_prompts_and_honors_decisions`

**PROTO-008 (MUST)** `auth_status` reports every bundled provider's `configured`, `usable`, `source`, `env_var`, and read error without returning a key; `auth_set_key` stores a non-empty key through `AuthStore` (mode `0600`, atomic write), optionally verifying it with the provider first; `auth_logout` removes it and reports whether one was present. Keys never appear in responses, logs, or error messages.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_008_auth_commands_store_and_remove_keys`

**PROTO-009 (MUST)** `get_catalog` returns the selectable models with provider, API, context window, and cost plus the provider list and the current selection; `get_config` returns effective provider, model, thinking, max turns, allow list, base URL, disabled extensions, and the config/auth/session paths with no secrets; `set_config` writes the same keys as `codie config set`, applies thinking, max-turns, and allow immediately, and reports `restart_required: true` for values that only take effect in a new process.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_009_catalog_and_config_round_trip`

**PROTO-010 (MUST)** `prompt.attachments` accepts `path` entries that expand like `@path` references and `image` entries carrying base64 data plus a `image/*` MIME type; attachment count and size limits are enforced, and rejected entries are reported in the prompt response's `warnings` without failing the run.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_010_prompt_attachments_are_inlined`, `crates/codie-cli/tests/rpc.rs::spec_proto_010_invalid_inline_image_is_reported`

**PROTO-011 (MUST)** The first record is `rpc_ready` with `version: 2` and a `features` array covering `permissions`, `auth`, `catalog`, `config`, and `attachments`; a version 1 ready record without `features` still deserializes, and a client that never sends a version 2 command observes version 1 tool policy.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_011_handshake_advertises_v2_features`, `crates/codie-protocol/src/lib.rs::v1_ready_records_still_parse_without_features`

**PROTO-012 (MUST)** `get_themes` returns every built-in palette except `system`, each with its stable name and the 29 semantic colors as lowercase `#rrggbb` strings; `system` is resolved by the client from its own appearance setting.
Verification: `crates/codie-cli/tests/rpc.rs::spec_proto_012_themes_are_semantic_hex_palettes`

# Data shapes

```text
{"type":"rpc_ready","version":2,"features":["permissions","auth","catalog","config","attachments"]}
{"type":"permission_request","version":2,"id":"perm-1","tool_call_id":"call_7","tool":"edit","arguments":{...}}
{"type":"response","version":2,"id":"answer","command":"permission_response","success":true,"data":{"request":"perm-1","decision":"allow_once","applied":true}}
```

Commands added in version 2:

| Command | Fields | Response data |
|---|---|---|
| `set_permission_mode` | `mode`: `headless` \| `ask` \| `allow` | `mode` |
| `permission_response` | `request_id`, `decision` | `request`, `decision`, `applied` |
| `get_catalog` | — | `current`, `context_window`, `models`, `providers` |
| `get_themes` | — | built-in palettes as semantic hex colors |
| `get_config` | — | effective values and paths, no secrets |
| `set_config` | `key`, `value` | `key`, `value`, `restart_required` |
| `auth_status` | — | `providers`, `auth_path` |
| `auth_set_key` | `provider`, `key`, optional `verify` | `provider`, `configured`, `verified`, `restart_required` |
| `auth_logout` | `provider` | `provider`, `removed`, `restart_required` |

New stable error codes: `unknown_permission`, `unknown_provider`, `no_key_required`, `invalid_key`, `auth_failed`.

# Edge cases

- A second `permission_response` for the same request fails with `unknown_permission`; the first answer wins.
- `allow_always` adds the tool to the session allow set, so later calls skip the request.
- Aborting while a request is pending resolves it as a denial and emits no further request for that call.
- A client that disconnects with a request pending leaves the run cancelled and the tool denied.
- `auth_set_key` with `verify: true` performs one provider probe; a throttled response is treated as accepted and
  stored, matching `codie auth login`.
- Attachment paths resolve from the session working directory; missing, directory, oversized, duplicate, and
  non-image paths produce warnings, never a failed prompt.
- `set_config` thinking values are validated before the file is written, so an invalid level changes nothing.
- `set_config allow` replaces the configured pre-approval list for the session; tools granted with `allow_always` stay approved until the session ends.
- Provider changes through `set_config` require a restart; the current client stays connected to the old provider.

# Non-goals

- Structured session listing and resume over RPC (clients use `--resume` and `codie sessions list --json` for now).
- User theme files over RPC; `get_themes` exposes the built-in palettes only.
- Streaming model catalog updates; `get_catalog` returns the merged cache loaded at startup.
- Permission persistence to disk; `allow_always` is per session.
- TypeScript binding generation is tracked separately and does not change the wire contract.
